## Сутності та атрибути

### Parent 
- `parent_id`: int (PK)
- `first_name`: string
- `second_name`: string
- `email`: string
- `phone_number`: string
- `password_hash`: string

### Student
- `student_id`: int (PK)
- `first_name`: string
- `second_name`: string
- `birth_date`: date
- `grade_level`: int
- `email`: string
- `phone_number`: string
- `parent_id`: int (FK, null)
- `password_hash`: string

### Teacher
- `teacher_id`: int (PK)
- `first_name`: string
- `second_name`: string
- `email`: string
- `specialization`: string
- `is_active`: boolean
- `password_hash`: string

### Course
- `course_id`: int (PK)
- `title`: string
- `level`: string
- `description`: string
- `price`: number
- `teacher_id`: int (FK)
- `is_active`: boolean

### Lesson
- `lesson_id`: int (PK)
- `course_id`: int (FK)
- `scheduled_at`: datetime
- `link`: string
- `recording_url`: string

### Homework
- `homework_id`: int (PK)
- `lesson_id`: int (FK)
- `title`: string
- `description`: string
- `due_date`: date
- `attachment_url`: string

### Homework_submission
- `homework_submission_id`: int (PK)
- `student_id`: int (FK)
- `homework_id`: int (FK)
- `submitted_at`: datetime
- `file_url`: string
- `grade`: number
- `feedback`: string
- `status`: string
- `graded_at`: datetime

### Subscription
- `subscription_id`: int (PK)
- `student_id`: int (FK)
- `course_id`: int (FK)
- `start_date`: date
- `end_date`: date
- `payment_method`: string
- `price`: number

## Зв'язки

|      Звʼязок     | Кардинальність |  Пояснення  |
| ---------------- | -------------- | ----------- |
| Parent - Student | 0..1 - N      | Опікун може мати кількох дітей, одна дитина має одного опікуна (або немає, якщо дитині не виповнилось 14 років) |
| Teacher - Course | 1 - N | Викладач може вести кілька курсів, курс може мати одного викладача |
| Course - Lesson | 1 - N | Курс складається із кількох занять, заняття може належати одному курсу |
| Lesson - Homework| 1 - 0..1 | На одному занятті можуть можуть задати одне домашнє завдання, кожне завдання належить ріно одному заняттю |
| Student - Homework_submission | 1 - N | Учень здає багато домашніх робіт, та кілька разів одне й те саме |
| Homework - Homework_submission | 1 - N | Одну домашню роботу здають кілька учнів або один учень|
| Student - Subscription | 1 - N | Учень може мати кілька підписок, певну підписку може мати один учень |
| Course - Subscription | 1 - N | На курс може бути кілька підписок, певну підписку може мати один курс |

## Критерії прийняття

### 1. Реєстрація користувачів (Parent, Student)

- cистема повинна зберігати для кожного учня ім'я, прізвище, дату народження, клас, email, телефон і посилання на опікуна;
- коли користувач надсилає форму реєстрації з коректними даними, система повинна створити обліковий запис і надіслати лист із підтвердженням email.
- якщо email уже використовується в системі, тоді система повинна відхилити реєстрацію та показати повідомлення про існуючий акаунт.
- система повинна зв'язувати кожного учня (до 14 років) рівно з одним опікуном, а одного опікуна — з довільною кількістю учнів.
- коли опікун відкриває особистий кабінет, система повинна показати список усіх його дітей.
- система повинна дозволяти створювати акаунт учня віком до 14 років лише з облікового запису опікуна.
- коли авторизований опікун надсилає форму створення акаунта дитини віком до 14 років із коректними даними, система повинна створити акаунт учня й автоматично записати `parent_id` цього опікуна.
- система повинна вимагати пароль під час реєстрації опікуна й учня та зберігати лише його хеш у `password_hash`.
- система повинна дозволяти опікуну та учню, викладачу змінити власний пароль після введення поточного.

### 2. Адміністрування викладачів і курсів

- система повинна дозволяти створювати, редагувати та деактивувати акаунти викладачів і курси лише користувачам з роллю адміністратора.
- коли адміністратор надсилає дані викладача (ім'я, прізвище, email, спеціалізація), система повинна створити акаунт викладача й надіслати на його email запрошення з посиланням для встановлення пароля.
- коли адміністратор створює курс і призначає йому викладача, система повинна зберегти курс і прив'язати його до цього викладача.
- якщо ціна курсу менша або дорівнює нулю або обов'язкові поля не заповнені, тоді система повинна відхилити збереження курсу та вказати, які поля некоректні.
- система повинна забезпечувати, що кожен курс має рівно одного викладача, а викладач може вести кілька курсів.
- система повинна дозволяти викладачу редагувати лише власні курси.
- коли адміністратор деактивує викладача, система повинна встановити `is_active = false`, заборонити цьому викладачу вхід і створення нових занять та домашніх завдань; уже створені курси, заняття й оцінені роботи зберігаються.
- коли адміністратор надсилає дані викладача і задає початковий пароль, система повинна створити акаунт викладача та зберегти хеш пароля в `password_hash`.
- система повинна дозволяти авторизованому викладачу змінити власний пароль після введення поточного пароля.
- коли викладач успішно змінив пароль, система повинна зберегти новий хеш у `password_hash`, і початковий пароль більше не діє.

### 3. Заняття

- коли викладач додає заняття до курсу з датою/часом і посиланням, система повинна зберегти заняття й зробити його видимим учням із активною підпискою.
- поки підписка учня на курс активна, система повинна надавати доступ до посилань на заняття цього курсу.
- де для заняття доступний запис, система повинна показувати його учням з активною підпискою в розділі «Записи».

### 4. Домашні завдання

- коли викладач створює домашнє завдання до заняття свого курсу, система повинна вимагати `title`, `description` і `due_date`.
- cистема повинна дозволяти опційно додати `attachment_url` (посилання на тест чи матеріал на зовнішній платформі).
- якщо обов'язкові поля не заповнені, тоді система повинна відхилити збереження та вказати, які поля некоректні.
- коли викладач зберігає домашнє завдання, система повинна повідомити учнів курсу з активною підпискою про нове завдання.
- коли учень з активною підпискою натискає «Здати» до `due_date` (з прикріпленим файлом або без нього), система повинна створити здачу з `submitted_at` і статусом submitted.
- якщо учень додав файл, тоді система повинна зберегти його в `file_url`.
- якщо учень натискає «Здати» після `due_date`, тоді система повинна прийняти роботу зі статусом late.
- cистема повинна показувати викладачу список зданих і ще не перевірених робіт по кожному з його курсів.
- коли викладач переглядає здану роботу, система повинна показати прикріплений файл, якщо він є.
- Учень з активною підпискою може здати те саме домашнє завдання кілька разів; кожна здача створює окремий запис `homework_submission`.
- коли викладач виставляє `grade` (у межах 1–100) і за бажанням пише `feedback`, система повинна зберегти їх, записати graded_at і змінити статус на graded.
- коли роботу оцінено, система повинна повідомити учня й опікуна про результат.
- коли робота має статус graded, система повинна показувати учню `grade` і `feedback`.

### 5. Підписки та оплата

- коли учень (або опікун) успішно оплачує курс, система повинна створити підписку з `start_date`, `end_date`, `payment_method` і `price`.
- система повинна зберігати в підписці ціну курсу на момент оплати, незалежно від подальших змін ціни курсу.
- якщо оплата не пройшла, тоді система не повинна створювати підписку й повинна показати причину відмови.
- якщо в учня вже є активна підписка на цей курс, тоді система повинна відхилити повторну покупку.
- поки підписка прострочена, система повинна пропонувати учню її продовжити.
- коли до `end_date` залишається 3 дні, система повинна надіслати нагадування учню та опікуну.
- якщо учень або опікун не продовжили підписку протягом 7 днів після `end_date`, то система має закрити доступ до курсу
- система повинна дозволяти учню мати кілька підписок (на різні курси), а кожна підписка належить одному учню й одному курсу.
- якщо учню менше 14 років, система повинна дозволяти опікуну оплатити підписку від свого імені.

### 6. Доступ і безпека

- якщо неавторизований користувач намагається відкрити захищену сторінку, тоді система повинна перенаправити його на сторінку входу.
- система повинна показувати учню лише його власні дані, опікуну — дані його дітей, викладачу — дані його курсів і робіт його учнів.
- система повинна зберігати персональні дані неповнолітніх відповідно до законодавства про захист персональних даних.
- адміністратор є лише роллю доступу в системі й не моделюється окремою сутністю
